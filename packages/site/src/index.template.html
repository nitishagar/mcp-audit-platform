Why mcp-audit?

Every finding traces to an executed check with named evidence — config key, schema field, CVE id. The core runs offline and deterministically: same input, same findings, byte for byte. Secrets it meets are redacted from every output; findings name locations, never values. 

$ mcp-audit scan mcp.json --format summary

  payments-remote is remote with no authentication configured

FAQ

Do you test live systems?
No. mcp-audit performs static analysis of your MCP configuration — not a penetration test. It never probes live systems or runs attacks. For adversarial testing, pair it with a red-team firm; our report makes their scoping call shorter.
Which framework do findings map to?
OWASP MCP Top 10 v2025-beta, with CVE references where research ties one. Unmapped patterns default to medium and are flagged, never silent.
Do my configs leave my machine?
No. The scanner is offline and dependency-free at runtime. Snapshot and Deep Audit review only the report artifacts you choose to send.
What does the scanner not cover?
Runtime behavior, live attack resistance, and supply-chain vetting of third-party server code. Those are human-review items in the Deep Audit tier.
